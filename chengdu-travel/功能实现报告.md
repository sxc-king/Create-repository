## 一、改造目标与结论

原站为「成都文旅推荐站」：首页（Hero + 热门景点 + 笔记）+ 六大商品栏目（住宿 / 美食 / 购物 / 玩乐 / 向导 / 攻略）+ 详情页 + 一次性订购页。它是典型的「货架电商」形态：商品分类为入口，订单结束即服务结束。

本次依据 MD 的核心理念 **「求同存异，体验优先」**，把站点改造成 **「旅程优先」的途伴 JourneyMate**：



* **同**：保留标准电商能力（酒店、门票、美食、向导等可预订，保证基础交易能力）

* **异**：产品架构主线从【商品分类】改为【旅客旅程】；核心资产从【库存】改为【旅客行程、偏好、协同关系、服务记录】；AI 从【独立聊天框】变为【贯穿售前 / 售中 / 售后的随行管家】

一句话：**用户不再是「来搜酒店」，而是「来构思一趟旅行」，预订只是行程里的一个动作。**

## 三、架构与数据模型

### 3.1 分层（对齐 MD 技术架构建议）



```
┌─────────────────────────────────────────────┐
│  上层：旅程优先体验                          │
│   (售前规划 → 售中随行 → 售后沉淀 + AI 贯穿)  │
├─────────────────────────────────────────────┤
│  中层：旅程连通中台（差异化核心）              │
│   store/trip.js 行程主数据 + 协同 + 事件通知   │
├─────────────────────────────────────────────┤
│  底层：标准交易层（求同）                     │
│   store/order.js 订单 + 原六大栏目资源库       │
└─────────────────────────────────────────────┘
```

### 3.2 旅程数据结构（一等公民）



```
{
  id, name, destination, startDate, endDate, budget,
  tags[], source('blank'|'ai'|'template'|'clone'),
  status('draft'|'ready'|'ongoing'|'finished'),
  owner,
  companions: [{ name, role('edit'|'view'|'notify'), avatar }],
  days: [{ title, nodes: [{
    id, type('activity'|'service'), name, time, location, note,
    price, img, category?, itemId?, orderId?, linked?
  }] }],
  comments: [{ id, user, text, time }],
  createdAt, updatedAt
}
```

### 3.3 订单是旅程的子资源



```
order = { id, category, itemId, itemName, date, count, name, phone,
          payType, amount, journeyId, status, createTime }
```



* 一份旅程可绑定 0\~N 个订单；订单创建后通过 `journeyId` 回写旅程服务节点，并推送订单消息。

* 订单中心可一键跳转所属旅程（`/trip/:id`）。

### 3.4 持久化

旅程、订单、消息、偏好、收藏、评价均写入 `localStorage`，刷新不丢失；首次访问自动注入 2 份演示旅程。

## 四、各模块实现说明

### 1. 首页（旅程优先）



* 首屏左卡片「开启一段新旅程」（✨AI 帮我规划 / 📝空白自建行程），右卡片「我的旅程」最近 3 条 + 状态标签。

* 第二屏「快速预订」（酒店 / 门票攻略）弱化呈现。

* 第三屏「灵感模板推荐」卡片一键复刻。

* 保留「热门景点」「成都笔记」作为内容资源区。

### 2. 我的旅程中心（`/trips`）



* 状态 Tab（全部 / 草稿 / 待出发 / 进行中 / 已结束）+ 计数。

* 旅程卡片：名称、状态、目的地、日期、预算、标签、来源（AI 生成 / 自建 / 模板复刻 / 旅程复刻）、天数 / 节点数 / 同行数。

* 空状态引导新建或询问 AI。

### 3. 新建旅程（`/trips/new`）



* 基础信息：名称、目的地、出发 / 返程日期、预算区间、出行标签（亲子 / 老人友好 / 徒步 / 摄影 / 吃货 / 慢节奏 / 夜游）。

* 两个入口：✨AI 帮我规划（携带参数跳 `/ai` 自动生成）、📝空白自建（建草稿进详情）。

### 4. 旅程详情（`/trip/:id`，核心页面）



* **左栏（桌面常驻）AI 随行管家**：上下文绑定本旅程；快捷指令（调整明天行程 / 适合老人吃饭 / 酒店评价 / 加熊猫基地 / 安排火锅）；智能回复可「加入第 N 天」。

* **中间时间线**：Day 分组、标题可编辑、节点增删改、跨天移动、活动 / 服务两类、加天数；服务节点带「去预订 / 查看订单」。

* **右栏同行 & 订单面板**：添加同行 + 权限下拉 + 移除；同行讨论区；关联订单列表 + 去预订。

* **底部工具箱**：导出 PDF（打开打印窗口）、分享链接（复制）、复刻行程（新草稿）、归档、推进状态。

### 5. AI 旅行管家（`/ai`）



* 多轮对话；输入需求（目的地 / 天数 / 同行人 / 预算 / 喜好）→ 识别关键词 → 生成 2 版方案（休闲 / 紧凑）切换查看。

* 方案内含：Day 时间线预览、**可预订询价卡片**（标注「价格实时查询，库存以供应商为准，AI 不保证有房」）、**风险提示**（节假日人流、老人避高强度徒步、亲子选商圈酒店）。

* 底部操作：「采纳方案，存入我的旅程草稿」（新建旅程并跳转）、「继续调整」。

* 未登录也可使用（存为游客草稿）。

### 6. 灵感广场（`/inspiration`）



* 6 套成都模板（亲子 / 美食 / 经典 / 周边 / 夜游），分类筛选，一键复刻为草稿旅程（V1.0 无 UGC 社区，符合 MD 砍复杂度）。

### 7. 预订 & 订单（依附旅程）



* 订单页顶部「当前归属旅程」提示条；可勾选绑定 / 不绑定。

* 下单后：创建订单 → 绑定旅程 → 回写服务节点 → 推送订单消息。

* 订单中心：状态分组、确认完成、取消、跳转所属旅程。

### 8. 个人中心 & 消息



* 出行偏好（10 项，AI 规划自动参考）；收藏（模板 / 酒店）；节点评价（绑定消费项目）。

* 消息中心：行程通知 / 同行邀请 / 订单通知 / AI 消息，未读红点 + 全部已读；头部铃铛实时未读数。

## 七、未实现项与后续建议（诚实说明）

本版为 **V1.0 前端演示实现**，受纯前端、无后端 / 无真实供应商限制，以下为 **未实现 / 需后续接后端** 的项：



1. **AI 接真实大模型**：当前为规则式生成，未接 LLM API、Function Calling、实时库存 / 价格查询；AI 的「询价卡片」为站内示意数据。

2. **供应链对接**：酒店 / 门票为静态示意数据，无真实分销接口、退改规则、库存实时同步（MD 建议起步走第三方分销）。

3. **跨端实时协同**：同行协同（评论 / 节点同步 / 位置共享 / 实时通知）为本地演示，未做 WebSocket 实时同步、短信 / 站内信推送。

4. **账号与权限系统**：登录为 localStorage 演示（admin/123456），无服务端用户体系、分享链接防刷、邀请防骚扰。

5. **AI 售中随行**：航变 / 闭园自动预警、一键改退等事件监听为概念演示，未接真实事件源。

6. **售后 AI**：游记 / 短视频生成、记忆相册未实现（MD 归入 V2/V3）。

7. **埋点与指标**：未做埋点统计（行程创建量、协同率、AI 使用率、复刻率等）。

**推荐落地顺序**（对齐 MD）：先聚焦「行程协同 + AI 随行管家」核心，用小步迭代验证用户是否接受「先建行程再预订」，再逐步接入交易与社交。
